# Demo：5 天合成语料 + 22 题

这个目录让任何人 clone 后 **30 秒内看到工具在跑**，不需要接入自己的记忆系统。

## 跑起来

```bash
python3 scripts/golden_eval.py \
  --golden demo/golden.json \
  --corpus demo/corpus \
  --out    demo/reports \
  --variant question
```

预期输出：

```
[question] G01 HIT  ...
...
=== 汇总（不含 3 道拒答题）===
question  n=19  recall@top3=100.0%  hit@any=100.0%  p50=204ms  p95=707ms
```

## 为什么是 100%

因为演示语料只有 **5 天、20 条事实**，而且题目是照着它写的。
这**不代表**真实语料的难度——真实部署上同一套工具测出来是 **92.3%**（见 [METHODOLOGY.md](../METHODOLOGY.md)）。

demo 证明的是三件事：

1. 检索能返回 `文件:行号`（不是模糊片段）
2. 判定口径能跑通（证据是否落在前 3 条）
3. 拒答题不会被算进 recall 分母

## 语料长什么样

```
- 2026-01-05T09:15:00+08:00 [自动捕获] 助手完成部署：订单网关 gateway 部署在 10.0.0.5，端口 8080
- 2026-01-05T10:15:00+08:00 [自动捕获] 用户决定把默认模型从 model-a 切到 model-b
- 2026-01-09T09:15:00+08:00 [自动捕获] 模型事故：model-b 在长尾请求上慢 2.3 倍，回滚到 model-a
```

一行一条事实、带 ISO 时间戳——这是让"行级检索 + IDF 打分 + 时间冲突判定"能工作的前提。

## 题目套路（值得抄）

| 类型 | 策略 | demo 里对应 |
|---|---|---|
| 时间推理 | 问"哪天/什么时候"，答案不在问句里 | G19 |
| 冲突 | 先问"从什么切到什么"，再问"现在是什么" | G02 → G03 |
| 跨会话 | 问几天前的事实，不给提示 | G06 |
| 指代 | 只给一个数字/代号 | G18 |
| 拒答 | 库里根本没有，看它会不会编 | G20 / G21 / G22 |

**拒答题是最有价值的一类**——它测的是"系统知不知道自己不知道"。
