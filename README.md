# memory-ops

给你的 Agent 记忆系统装**仪表盘**和**刹车**。

不是又一个记忆框架——它不存记忆，只回答三个问题：

1. 它现在到底行不行？（**基线**）
2. 坏了以后我多久能知道？（**探针**）
3. 下次改动会不会悄悄把它改坏？（**门禁**）

> 真实部署案例：同一套存储、同一批数据，一天之内整句召回 **57.7% → 92.3%**，
> 假拒答 **50% → 0%**。全过程（含三个被数据否决的方案）见 [METHODOLOGY.md](METHODOLOGY.md)。

---

## 为什么需要它

用久了的记忆系统通常死于三件事，而不是算法不够好：

| 病 | 表现 |
|---|---|
| **静默失败** | 索引写不进去，降级到缓冲，30 分钟重试空转，没人知道 |
| **无判据** | 改完感觉"好像更好了"，下次又感觉"好像变差了" |
| **缓存腐烂** | 编译出来的快照半年没更新，却被当作"现状"注入上下文 |

这三种病都不会让系统立刻报错——它们让系统**安静地变笨**。

## 快速开始（30 秒，不需要接入自己的系统）

```bash
git clone <this-repo> && cd memory-ops
python3 scripts/golden_eval.py --golden demo/golden.json --corpus demo/corpus --out demo/reports
```

输出会告诉你：19 道可答题的 `recall@top3`、延迟 p50/p95，以及 3 道拒答题被正确排除在分母之外。

接自己的系统时，只需让 `memory_recall.py` 能读到你的每日笔记目录：

```bash
MEM_DAILY_NOTES_DIR=~/notes python3 scripts/golden_eval.py --golden my-golden.json
```

## 这四件东西分别解决什么

### 1. 检索能回指到行

```
2026-01-05:3  gateway 部署在 10.0.0.5，端口 8080
```

没有 `文件:行号`，就无法判分、无法审计、无法从 SoT 重建索引。
这是所有后续工作的前提，也是它自己最先被加上的一项。

### 2. 查询改写（收益最大的一项）

```
"9 月 21 日那次清理后，队列剩余多少条？"
  → "09-21 那次清理后 队列剩余 条 构成"
```

去掉疑问词和语气尾缀、把日期归一成 ISO 格式。
实测 **+19.2 点**，比让 LLM 改写（+11.5 点）更好，且零延迟、零外部依赖。

### 3. 探针只在"看得见"的地方报警

外部推送渠道死了以后，落盘日志等于没告警。
所以红灯会注入**下一次模型会话的第一条消息**——那是唯一保证被看到的地方。

### 4. 门禁（防退化）

```
每周日 07:00 → 跑 30 题 → 与已接受基线比较
  > +3 点  绿（能力提升）
  ±3 点    绿（正常波动）
  -3~-8    黄
  < -8     红 → 注入会话
```

规则很硬：**改前跑、改后跑，降幅 >3 点直接回滚代码**。

## 口径（先定死，否则数字没意义）

| 指标 | 定义 |
|---|---|
| `recall@top3` | 前 3 条结果里是否包含应命中证据（按位置判定，不看措辞） |
| 拒答正确率 | 库内无记录时，是否明确说「无记录」 |
| 假拒答率 | 库内有答案，却回了「无记录」 |
| 无据断言率 | 回答中的陈述在检索材料中找不到依据 |
| 冗余密度 | 前 5 条去重后的有效条数（替代模糊的"冗余率"） |

## 几个坑（都踩过）

- **`MAX_TOKENS=3`**：查询词超过 3 个就被截断。系统"支持多关键词"是假的。
- **行级窄窗口**：以为更精准，实测召回 −11.5 点——答案常跨相邻行。
- **让 LLM 复判确定性事实**：同一句「无记录」被判 True 和 False，指标直接失真。
- **陈旧缓存**：7 天没更新的快照比没有快照更有害，因为它会被当作现状。
- **闸门比存储重要**：它不让你记得更多，它让你**知道**自己记得怎么样。

## 适用前提

- 记忆事实以**纯文本、一行一条**的形式落盘（这是行级检索和冲突判定的基础）
- 有至少 3 个月的真实历史可挖题
- 接受"先量、再改"的顺序

如果你的记忆完全是向量库黑盒、没有可读的原始记录，这套工具的价值会大打折扣——
因为它的核心是**拿原始记录当唯一真相**，索引只是可以随时重建的派生层。
